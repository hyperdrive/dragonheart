# Scene-wide y-sort (fake depth) — decisions

Date: 2026-11-13. User: "We need to sort the rendering of the objects in
the scene. Each object has a base, for example a soldier's base is his
legs, a mountain has a mountain base etc. All objects should be sorted in
y direction so that we get a fake sense of a z-direction in the scene. A
flying dragon should also be rendered on top of everything else."

## Decisions

| Decision | Choice | Why | Revisit when |
|---|---|---|---|
| Sort containers | `y_sort_enabled = true` on BOTH `World` AND `World/WorldManager` in Main.tscn. Y-sort merges through NESTED containers: a child of a y-sorted parent is sorted with its parent's siblings as long as every intermediate Node2D is also y-sorted | WorldManager spawns everything (NPCs, props, drops) as its own children; Dragon is a direct child of World. Enabling both puts all world objects into ONE sort pool | an object stops sorting correctly after a parenting change |
| Sort key = the object's BASE | Every object's visual is shifted so its base (feet/ground contact) sits at the NODE ORIGIN; the origin's y is then the sort key. Measured per scene with `testfiles/measure_bases.gd` (ColorRect-accurate) + `measure_bases_alpha.gd` (opaque-pixel row for SVG sprites) | User's spec — "each object has a base". Origin-at-base also makes the dragon's feet, NPC feet and prop bases comparable | — |
| Flat ground stays below actors | City, Lake, Field get `z_index = -1` and are NOT base-shifted — they are ground planes, not standing objects | City compound/water/soil should never occlude actors standing on them; z −1 pins them under the whole y-sorted pool. City keeps its origin: the gate/rally offsets (rally 0,−120; town 0,−90; king 0,−140; adventurer anchor 0,−90) couple to the city center | — |
| NPC base shifts | Sprite container moves so feet land at origin: Farmer/Miner −23, Goblin −18, Soldier/Archer −26, Wizard −30, King/Adventurer −54. Miner's haul Cart (runtime-toggled) moves (26,8) → (26,−11) so its wheels share the new ground line (originally wheels 19 / boots 18 — same ground) | Measured boots bottom per scene; the original Sprite (0,−5) put feet 18–59px below origin | — |
| Prop base shifts | Tree sprite −27 (design trunk line ≈9 kept, per 2026-11-09 tree record), TrunkShadow offsets −1..5; Mountain sprite −84; DragonLair sprite −105 (scale 1.5); WizardTower sprite −120; GoldDrop sprite −11 + Glow −22 | Measured opaque bases (SVG margins are transparent — alpha measurement is authoritative for sprites) | hand-drawn art replaces composites |
| Dragon base | Vis at (0,−23): Body underside (Sprite-space 28) minus Sprite's own −5 = 23 below origin. `Dragon.VIS_BASE_LIFT = 23` re-applies it in `_tick_flight_visual` (which owns vis.position.y every frame), so flight lift/bob ride ON the base offset. Shadow offsets −3..4 preserve the original shadow-vs-feet relation (bottom = feet + 4). FireArea mouth anchor ALSO rides −23 (flame + ignition reach originate at the mouth; `_apply_facing` flips only x, so the tscn y is authoritative) — an earlier "legs at 40 → −35" theory was wrong (the +12 residual was the Flame assembly at its old feet-level position, not feet) and was reverted; with FireArea at −23 the dragon scene measures a clean 0 | The mouth and feet must both track the base shift — a shifted body with an unshifted fire origin breathes from the feet (user-reported 2026-11-13) | dragon art gains real legs or a taller fire cone |
| Flying dragon on top | `z_index = 100` in `_try_flight`, `z_index = 0` in `land_flight` | y-sort orders GROUNDED objects; a flyer must jump the whole pool. z_index overrides y-sort within the container | an object needs to render above the flying dragon |
| Left as-is | PigPen/CowPen (46 residual — AnimalPen runtime children make shifting risky), Sacrifice (runtime visuals), BaseNPC flames (z2), pen child z2, Field crop layers | Intentional residuals, documented here | a pen/sacrifice layering bug is observed |

## Measurement trap (documented)

`measure_bases.gd` v1 did NOT accumulate parent Node2D y into ColorRect
bottoms — the first NPC numbers were mixed-space and the shifts were
over-corrected by 5. Both measure scripts now accumulate correctly; the
alpha script initially had the same bug (fixed). Trust order: alpha
result for Sprite2D scenes, rect result for ColorRect scenes.
